# 45 项算法科学证据审查设计

## 1. 目标

对 `algorithm` 下 01–45 全部算法进行实现、科学文案与文献证据的闭环审查，使控制台全部可见文案、AI 解读知识和配套算法清单满足以下要求：

1. 公式、参数、分支、输入输出与实际代码一致。
2. 科学定义、物理机制、适用条件和限制有可追溯证据。
3. 教学实现、工程默认和文献方法明确区分。
4. 未实现能力不得出现在算法标题或完成性表述中。
5. 无法由证据支持的主张必须收缩、标明条件或删除。

审查覆盖：

- `algorithm/web/src/principles/*.ts`
- `algorithm/web/src/sources.ts` 及后续证据结构
- `algorithm/web/src/wayho/*.ts`
- `algorithm/source/common/console_output_knowledge/*.py`
- `algorithm/source/common/l3_aide/*.py`
- `algorithm/source/algorithms/*/service.py`
- `algorithm/source/common/rs/*.py`
- `algorithm/docs/采集到算法-算法清单.md`
- `algorithm/docs/算法API测试清单.md`

## 2. 证据口径

证据按以下优先级采用：

1. 同行评审原始论文或公认方法论文。
2. 正式国际、国家、行业标准。
3. 政府机构、标准组织、软件项目官方技术文档。
4. 同行评审综述、专著或可信课程材料，仅用于方法背景。
5. 二手索引库、题录页和聚合网站只能辅助定位原文，不能作为公式、首创或强科学结论的唯一证据。

工程类算法没有唯一原始论文时，可采用标准或官方技术文档证明工程方法。具体阈值、默认参数或仓库特化流程若没有文献来源，必须标为“本仓库工程默认”，不得写成行业规定。

## 3. 机器可读证据模型

建立 45 项统一科学证据清单。每项算法包含以下信息。

### 3.1 实现证据

- 算法 ID 与当前标题。
- `service.py` 入口。
- 核心实现函数及源码位置。
- 实际公式、默认参数和条件分支。
- 实际输入、输出文件和 API 返回字段。
- 当前未实现能力。

### 3.2 科学主张

每条主张至少包含：

- `claimId`：算法内稳定标识。
- `category`：定义、公式、输入、输出、机制、限制、适用范围、产品规格。
- `text`：经审查后允许展示的标准表述。
- `targets`：该表述出现或约束的页面、AI、输出知识或文档位置。
- `status`：
  - `supported`：来源直接支持。
  - `qualified`：来源有限支持，展示时必须保留条件。
  - `implementation-only`：本仓库工程行为，不冒充文献结论。
  - `rejected`：无证据、与实现冲突或夸大，禁止展示。
- `referenceIds`：支持该主张的文献。
- `implementationRefs`：支持该主张的源码或测试。
- `reviewNote`：实现差异、适用边界和审查说明。

### 3.3 文献记录

每条文献至少包含：

- 稳定文献 ID。
- 作者、年份、题名、期刊/机构。
- DOI 或官方持久链接。
- 来源类型与证据等级。
- 经原文或官方页面核对的中文内容提要。
- 该来源实际支持的 `claimId`。
- 无法获取全文时的明确状态，不得把搜索摘要当作全文结论。

## 4. 证据等级

- **A**：原始论文、正式标准或官方资料直接支持核心公式/方法，且实现差异已披露。
- **B**：权威来源支持方法族，仓库实现有明确简化，正文与文献页完整披露差异。
- **C**：只有工程文档、综述或部分证据；仅允许有限表述，必须标明工程实现或证据边界。
- **D**：引用与主张不匹配、只有二手来源支撑公式，或主张与实现冲突。D 级不得上线。

## 5. 单算法六道审查门

### 5.1 实现取证

从 `service.py`、`common/rs` 和测试提取真实公式、默认参数、分支、输出键与未实现能力。以代码和运行结果为准，不以现有标题或文案反推实现。

### 5.2 科学核验

用原始论文、标准或官方文档核对定义、公式、机制、适用条件和限制。链接需实际打开，关键结论需核对摘要或正文。

### 5.3 多处对齐

同步检查原理页、文献页、产品分析、输出知识、AI 解读知识和两份清单文档。相同主张可以按页面目的改写，但不得改变科学含义或删除限定条件。

### 5.4 标题诚信

标题只保留已实现能力。规划能力、行业完整做法和未实现分支放入“实现差距”，不得继续作为已完成标题。

### 5.5 实现修复

实现存在可确认错误时修代码，不得只靠文案免责声明掩盖。每个行为修复先增加失败测试，再实施最小修复。

### 5.6 逐项结论

记录证据等级、修订内容、剩余限制和验证结果。D 级必须修复或删除相关主张；C 级必须保留限定语。

## 6. 已确认的高风险问题

首轮只读审查已确认以下问题，实施阶段须优先处理。

### 6.1 实现或返回错误

- #32：未执行 SNV 时，响应仍固定回显 `preprocess: "snv"`。
- #25：前三个原始光谱波段被 SLIC 默认按 RGB 转换到 Lab，科学语义不成立。
- #17：两景 CRS 不一致时未拒绝，直接合并 bounds 会产生无效几何。
- #45：统计未排除 NoData。

### 6.2 文案与实现硬冲突

- #05：页面写“白度高”，实现条件是光谱起伏指标低于阈值。
- #07：API 方法名写“双线性填充”，实现是 3×3 邻域均值。
- #09：输出知识写“标定偏移”，实现是场景互相关估计。
- #15：定义写位置与姿态投影，实现不使用姿态。
- #20：实现指标为场景全图 `mean/std`，不能称为传感器 SNR。
- #31：导数窗口文案为 680–750 nm，代码上限为 760 nm。
- #34：页面要求 SVM 标准化，实现未标准化。
- #35：页面输出名与 API 文件键不一致。

### 6.3 标题包含未实现能力

- #03：标题含 GPS+IMU，但没有原始 IMU 比力/角速度积分。
- #04：标题含丢帧，但没有丢帧检测。
- #18：标题含接缝线优化，但没有接缝线搜索。
- #19：标题含矢量配准，但只有影像全局平移。
- #36：标题含 RNN，但只有 1D-CNN。
- #38：标题含 GCN，但只有 Transformer。
- #39：标题含迁移学习，但实现为均值原型 + SAM。
- #40：标题含语义分割，实际为低 NDVI 种子 + ACE + 阈值斑块。

### 6.4 文献与主张失配

- #05：完整 Fmask 论文不能直接证明本仓库无热红外简化阈值。
- #07：EMVA 1288 不直接规定本仓库 6σ 残差方法。
- #15：精密直接地理定位论文不直接证明无姿态的 GSD 仿射粗定位。
- #16：现有综述摘要不支持共线方程 + DEM 正射具体方法。
- #17：现有来源不直接支持距离羽化。
- #18：缺标准 Wallis 方法的直接来源。
- #28：NDRE 公式主要依赖二手索引库，须核对 Barnes 2000 可访问原文。
- #40：现有引用对 ACE 与“语义分割”标题支持不足。

## 7. 实施顺序

1. 修复硬错误、错误返回和标题虚假能力。
2. 为 P0/P1 文献缺口核对或补充直接来源。
3. 修正绝对化、营销化和跨文件漂移。
4. 建立 45 项机器可读证据清单及文献—主张绑定。
5. 让文献页展示来源具体支持的主张及证据等级。
6. 增加静态一致性、公式 golden、标题诚信和来源完整性测试。
7. 运行 45 项冒烟、后端测试、前端类型检查与生产构建。
8. 生成 45 项审查报告并通过 Canvas 展示。
9. 仅在无 D 级、P0/P1 全部关闭且全量测试通过后更新线上。

## 8. 自动验收

### 8.1 完整性

- 45/45 算法均有证据记录。
- 每项定义、公式、主要输入输出、关键限制均有文献证据或实现证据。
- 每条文献有中文提要及明确支持的主张。

### 8.2 一致性

- 公式与实现 golden test 一致。
- API 返回键与页面输出名一致。
- 原理页、输出知识、AI 解读和清单中的关键主张不得与证据清单冲突。
- 未实现能力词不得出现在算法标题和成功消息。

### 8.3 文献质量

- DOI、题名、作者和年份经 DOI、出版社或官方机构页面核对。
- Index Database、ADS、Semantic Scholar 等二手来源不得作为公式的唯一证据。
- 链接必须可打开；第三方 PDF 应优先替换为 DOI 或机构官方地址。
- 文献提要不得支持超出原文范围的结论。

### 8.4 运行验证

- 后端测试全通过。
- 前端测试与生产构建全通过。
- 45 项 testdata 冒烟全通过。
- 代表算法对关键公式和分支进行数值复算。

## 9. 不确定性处理

- 找不到原文：标“待核原文”，收缩正文，不写强结论。
- 仅支持方法族：标 `qualified`，明确本仓库差异。
- 仅为工程行为：标 `implementation-only`。
- 文献与代码冲突：以实际实现描述当前能力，同时决定修实现或修改方法名。
- 产品型号资料缺失：删除或降级相关产品分析，不凭印象补写规格。

## 10. 上线门槛

满足以下全部条件才允许部署：

1. 45 项均完成审查。
2. 无 D 级证据。
3. 所有 P0/P1 问题关闭。
4. 所有自动化测试与生产构建通过。
5. 审查报告列出所有 C 级主张及剩余风险。
6. 公网健康检查、45 项目录、代表性算法和证据页验收通过。

## 11. 交付物

- 45 项机器可读证据清单。
- 更新后的原理、文献、产品、输出知识、AI 知识和算法清单。
- 实现修复及回归测试。
- 文献—主张绑定展示。
- 45 项审查报告和 Canvas。
- 全量验证记录与线上验收记录。
