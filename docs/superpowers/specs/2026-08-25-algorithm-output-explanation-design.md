# 算法输出详细说明与专家分析工作台设计

## 1. 背景

算法控制台已覆盖 45 个算法的算法原理、运行演示和输入字段专业说明，但输出侧仍存在三个问题：

1. 输出文件虽然与服务真实返回键一致，说明多数来自按可视化类型生成的通用模板，缺少算法和产物级语义。
2. `data` 响应以一个通用对象展示，核心业务指标没有逐项解释。
3. 运行结果可视化与输出字段说明相互分离，用户看到了图或数值，却无法立即判断其含义、效果和可靠性。

本设计在不改变算法计算逻辑的前提下，为全部 45 个算法建立逐输出专业知识，并在运行演示中提供“专家分析工作台”。

## 2. 目标

### 2.1 核心目标

- 对所有真实输出文件逐项说明内容、结构、效果、质量检查和用途。
- 对 `data` 中影响业务判断的核心指标逐项说明。
- 同时解释视觉或数值表现、业务含义和效果好坏的判断依据。
- 运行前展示预期产物，运行后将真实结果绑定到同一说明。
- 兼顾领导快速阅读与专家深入分析。

### 2.2 非目标

- 不在本轮穷举 `data` 中所有调试信息、参数回显和内部中间字段。
- 不修改 45 个算法的计算实现和返回协议。
- 不根据单次运行结果无依据地宣称算法“效果优秀”。
- 不把 PNG 预览或颜色渲染当作定量结论来源。

## 3. 已确认决策

- 输出范围：所有文件输出全部说明，`data` 仅展开核心业务指标。
- 效果范围：同时覆盖画面或数值表现、业务含义和质量判断。
- 页面位置：运行前和运行后均展示。
- 技术方案：以后端逐算法输出知识库作为单一专业说明来源。
- 页面形态：采用“C · 专家分析工作台”，并保留领导摘要层。

## 4. 信息架构

### 4.1 顶部决策摘要

每个算法显示简短摘要：

- 本算法会产生哪些主要产物。
- 这些产物能够支持什么判断。
- 结果能否直接用于业务，或还需哪些检查和处理。

摘要默认可见，使用专业但易懂的表达，避免堆叠接口键和实现细节。

### 4.2 文件产物

每个 `files.*` 输出独立展示：

- 中文名称和真实接口键。
- 文件格式和数据结构。
- 单位、合理范围或类别编码。
- 多波段文件的波段顺序和每个波段的含义。
- 条件输出的触发条件。
- 预期视觉或数值效果。
- 业务含义和适用判断。
- 质量检查方法、异常表现及常见原因。
- 下游用途和禁止误用事项。
- 与其他输出的关系。

### 4.3 核心指标

只选择能够影响业务判断或质量判断的 `data` 字段：

- 指数类：最小值、最大值、均值、有效范围或有效像元比例。
- 分类类：OA、AA、Kappa、类别数和必要的样本统计。
- 回归类：R²、RMSE 及必要的样本统计。
- 检测类：阈值、目标数量、面积或像元数量。
- 质量控制类：是否通过、告警项、误差或异常比例。
- 地块统计类：场景汇总和地块级核心统计结构。

参数回显、格式标记和内部调试字段不单独建立专业卡片，仍可在原始返回数据中查看。

### 4.4 质量检查

质量状态采用三态表达：

- **通过**：有明确规则，且本次值满足规则。
- **需关注**：超出建议范围、存在异常表现，或需要人工复核。
- **不可判定**：缺少明确阈值、真值、业务基线或必要元数据。

合理范围是检查依据，不等同于跨传感器、跨区域和跨任务的统一合格标准。

### 4.5 下游应用

每个输出说明：

- 可直接用于哪些后续算法或业务。
- 使用前需要哪些转换、检查或配套数据。
- 哪些场景禁止直接使用。

## 5. 数据模型

新增独立的输出知识结构，建议对应前端类型如下：

```typescript
interface OutputFieldRow {
  name: string;
  apiKey: string;
  parent: "files" | "data";
  label: string;
  type: string;
  format?: string;
  description: string;
  unit?: string;
  range?: string;
  vis: VisKind;
  optional?: boolean;
  conditional?: string;
  bands?: Array<{
    index: number;
    label: string;
    unit?: string;
    range?: string;
    meaning: string;
  }>;
  effect: string;
  businessMeaning: string;
  interpretation: string;
  qualityCheck: string;
  abnormalSigns: string[];
  downstreamUse: string;
  misuseWarning?: string;
  relatedOutputs?: string[];
  example?: unknown;
}
```

### 5.1 字段语义

- `effect`：用户预期看到的图像、空间格局或数值变化。
- `businessMeaning`：该效果能够支持的业务判断。
- `interpretation`：如何结合单位、范围、类别或算法公式读结果。
- `qualityCheck`：判断输出是否可用的检查步骤。
- `abnormalSigns`：常见异常表现及问题线索。
- `conditional`：条件输出的产生条件。
- `bands`：多波段文件中各波段的固定顺序和语义。
- `relatedOutputs`：定量文件、预览文件和指标之间的对应关系。

## 6. 后端架构

### 6.1 输出知识库

新增 `algorithm/source/common/console_output_knowledge.py`：

- 按算法 ID 和完整输出路径维护专业知识。
- 完整路径示例：`files.ndvi_tif`、`data.mean`。
- 可复用少量格式级公共模板，但每个真实输出必须提供算法专属覆盖。
- 45 个算法服务文件不承载页面长文。

### 6.2 元数据组装

`console_catalog.py` 继续负责：

- 维护或生成真实文件输出骨架。
- 合并输出知识库。
- 向控制台接口返回结构化输出说明。

通用模板只作为开发期容错。正式完整性测试不允许真实输出仅使用通用兜底说明。

### 6.3 单一事实来源

- 输出键：以 `service.py` 实际返回为准。
- 专业说明：以输出知识库为准。
- 页面组件：只负责展示，不拼接专业长句。
- 算法原理：解释算法层面的结果含义。
- 输出工作台：解释逐产物和本次运行结果。

## 7. 前端专家分析工作台

### 7.1 运行前

在执行表单附近展示：

- 顶部决策摘要。
- “文件产物、核心指标、质量检查、下游应用”四个标签。
- 每个输出的预期结构、效果和判读规则。
- 条件输出的产生条件。

### 7.2 运行后

保持同一工作台结构并注入真实结果：

- `files_http` 按 API 键匹配文件产物说明。
- `data` 中已登记的核心指标匹配到指标说明。
- 实际值与单位、建议范围和质量状态并列。
- 可视化结果与对应输出说明同屏呈现。
- 预览 PNG 明确关联对应的定量文件。
- 多波段结果展示波段说明，不能只显示一个通用文件名。

### 7.3 阅读层级

- 领导默认看到决策摘要、主要产物和质量状态。
- 专家通过标签和展开项查看结构、指标、异常、质检依据与下游约束。
- 移动端使用纵向标签和卡片，不使用横向大表格。

## 8. 异常与边界处理

### 8.1 条件输出

- 未满足条件时显示“本次条件未满足”，不判定为运行失败。
- `40_detect_segment.files.annotation_geojson`：仅提供标注/AOI 辅文件时产生。
- `45_parcel_zonal_stats.files.parcel_geojson`：仅提供地块矢量时产生。

### 8.2 未登记输出

- 实际响应出现未登记键时仍显示原始值。
- 页面标记“说明待补充”。
- 完整性测试必须失败，阻止无说明的新输出长期进入界面。

### 8.3 无法自动判定

- 没有统一阈值时显示“不可判定”。
- 需要真值、样本、传感器元数据或业务基线时明确列出缺少条件。
- 不使用预览色带、单景相对值或通用经验阈值替代专业验证。

### 8.4 运行失败

- 保留预期输出说明供学习和排查。
- 单独展示服务错误。
- 不生成虚假的效果、质量状态或指标解释。

## 9. 内容编写标准

每条输出说明必须满足：

- 指向真实输出键，不使用模糊的“结果文件”。
- 区分数据值、预览颜色和业务结论。
- 数值范围明确标注单位、前提和是否为理论范围。
- 效果描述同时回答“看到什么、代表什么、如何判断是否可靠”。
- 说明多波段顺序、类别编码和 NoData。
- 写清错误使用可能造成的业务后果。
- 对领导可快速理解，对专家可追溯到接口字段和质量依据。

## 10. 测试与验收

### 10.1 后端完整性

- 45 个算法全部存在输出说明。
- 所有真实文件输出均有算法专属知识记录。
- 所有选定核心 `data` 指标均有知识记录。
- 元数据中的文件键与服务真实返回键一致。
- 条件输出具有 `conditional`。
- 多波段产物具有完整 `bands`。
- 所有输出具有 `effect`、`businessMeaning`、`interpretation`、`qualityCheck`、`downstreamUse`。

### 10.2 前端

- 类型检查通过。
- 生产构建通过。
- 运行前正确显示预期产物。
- 运行后文件和核心指标按真实键绑定。
- 条件未满足时不误报失败。
- 未登记输出显示“说明待补充”。
- 键盘和读屏可以访问标签、卡片、展开项和质量状态。

### 10.3 代表性端到端验证

至少覆盖：

- L0：质量报告或校正产物。
- L2：多波段预处理产物。
- L3 指数：定量 GeoTIFF、预览 PNG、统计指标。
- 分类：分类图、OA、AA、Kappa。
- 回归：反演图、R²、RMSE。
- 检测：得分图、掩膜、矢量和条件输出。
- 地块统计：场景汇总、地块统计和条件矢量。

## 12. 完成定义

当以下条件同时满足时，本功能完成：

1. 45 个算法所有文件输出均有专属详细说明。
2. 每个算法核心业务指标均有逐项说明。
3. 输出效果同时包含视觉或数值表现、业务含义和质量判断。
4. 运行前后使用同一份结构化知识。
5. 专家分析工作台完成文件、指标、质检和下游四类信息展示。
6. 后端测试、前端类型检查、生产构建和代表性端到端运行全部通过。
