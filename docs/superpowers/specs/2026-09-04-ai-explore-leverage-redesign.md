# AI 探索「大模型赋能分析」方案 A 设计

## 1. 目标

把算法页「AI 探索 → 大模型赋能分析」从固定三维护栏，改成有发挥空间的赋能说明：大模型如何提高本次运行、结果如何接到下游应用，同时保留科学限制与误用拦截。

本页回答三句话：

1. 大模型怎样让这次算法跑得更明白、更不容易用错。
2. 这次输出之后，典型下游应用怎么接，哪些还不是本页产品。
3. 哪些话不能说。

## 2. 非目标（本期不做）

- 不改「大模型赋能效果」的左右对照交互：仍用本次运行返回生成解读。
- 大模型仍不重算、不看影像、不改代码、不自动调参、不改推其他算法、不输出处方或业务决策。
- 不按 L0/L1/L2/L3/L4 做独立「层工作台」案例页（那是方案 B）。分层差异只写进各算法四段正文。
- 不把典型应用路径写成已经交付的业务产品。

## 3. 现状问题

赋能分析只渲染 `llmLeverage.dims` 的三维：

- `readout`「帮你读返回」
- `bounds`「点出方法限制」
- `guard`「拦住说错」

数据结构把 45 项锁死在同一骨架，所以即使用算法专属句子，看起来也永远只有三项，且三项都是护栏，没有「提高算法」和「接到应用」。

## 4. 页面结构

每项算法的「赋能分析」固定四段，顺序如下。

### 4.1 提高本次运行

说明大模型在**不重算**的前提下，如何提高本次使用质量。必须落到本算法真实参数与返回字段，例如波段索引、CRS、预处理开关、全图统计。

允许写：核输入是否匹配方法前提、解释本次参数选择、对照返回字段含义。

禁止写：大模型会改公式、重训网络、生成新立方体、自动替用户选定最终业务阈值。

### 4.2 接到应用

写 1–2 条**典型下游路径**，并必须标明：这是后续用法，不是本算法页面已经交付的业务产品。

允许写：相对分区、制图、作为下一处理步骤的输入图层、进入地块汇总。

禁止写：处方、喷药、产量、已经确认的病虫害、叶绿素毫克数、飞行合格证。

### 4.3 方法限制

沿用已审查的科学边界与实现差异。必须与 `scientific_evidence.json` 的 limitation / implementation-only 主张一致，不得另造机理。

### 4.4 拦住说错

沿用现有误用拦截。继续禁止把返回写成未登记物理量、处方或业务决策。

## 5. 分层只作为正文语气，不是单独模块

同层算法共用一组**写作重点**，但页面上不出现「本层工作台」导语块。

| 层 | 提高本次运行侧重 | 接到应用侧重 |
|---|---|---|
| L0 | 放行判断：过曝、同步、云影候选是否挡住后续 | 这包数据能否进入辐射/几何；不是飞行验收 |
| L1 | 暗场、定标系数、坏元方法是否匹配 | 得到可比较辐亮度；不是农情图 |
| L2 | CRS、波段选择、窗口与配准前提 | 交给指数/分类的立方体；不是地块结论 |
| L3 | 波段是否落在真实光谱窗口、指标/类别怎么读 | 相对分区、制图、进入汇总；不是定量产品或处方 |
| L4 | NoData、空区、统计口径 | 报表/专题图；不是原因或决策 |

## 6. 数据模型

扩展 `llmLeverage`，不再只用三维分数列表驱动整页。

每项算法提供：

- `improveRun`：提高本次运行（标题固定，正文算法专属）
- `toApplication`：接到应用（标题固定，正文算法专属，必须含下游限定语）
- `bounds`：方法限制
- `guard`：拦住说错

保留原三维分数仅用于「赋能效果」页的对照说明或内部计量，不再作为赋能分析页的唯一可见结构。若保留分数，不得在分析页暗示「科学正确率」。

`improveRun` 与 `toApplication` 必须绑定本算法 ID，禁止 45 项共用一句空泛默认文案充数。L0–L2 原先走 `_DEFAULT_LEVERAGE` 的，本期必须补专属四段。

## 7. 样例：27_ndvi

提高本次运行：对照本次 `red_band`、`nir_band`、值域和全图统计，核红光/近红外是否按传感器光谱响应选择，讲清每个返回字段。

接到应用：可用于同一传感器与处理链下的绿度相对分区，或作为地块汇总的输入图层。这是下游用法；本页只输出 NDVI GeoTIFF，不是叶绿素或生物量产品。

方法限制：应优先用定标反射率；高叶面积时容易饱和，对生物量增量的敏感性下降。

拦住说错：拦住把 NDVI 直接写成叶绿素含量或生物量定量产品。

## 8. 约束（继承科学审查）

- 标题与能力只写已实现部分。
- 教学默认参数不得写成行业标准。
- 不得推荐其他算法名称作为「下一步必做」。接到应用可写「进入地块汇总」这类交付形态，不点名推销未运行的算法页。
- 不得输出处方或业务决策。
- 应用路径必须带限定语：「后续用法 / 不是本页已交付产品」。
- 文案不得与 `scientific_evidence.json` 已核验主张冲突。

## 9. 实现落点

- 后端：`algorithm/source/common/l3_aide/knowledge.py` 的 `llmLeverage` 结构。同步修改 `interpreter.py` 的系统提示词：继续覆盖读返回、限制、拦住说错；并加入「若提到下游用法，必须标明不是本页已交付产品」。
- 前端：`algorithm/web/src/components/AiExplorePanel.vue` 赋能分析改为渲染四段，而不是 `dims` 三项列表。
- 测试：`algorithm/source/tests/test_l3_aide.py` 不再断言 45 项标签等于「帮你读返回、点出方法限制、拦住说错」三元素；改为断言四段存在、应用段含下游限定语、护栏段仍禁止处方。
- NDVI 专项：四段必须包含反射率优先、饱和、不能直接作为叶绿素/生物量定量产品。

## 10. 验收

- 45/45 均有四段专属正文，无空泛默认句充数。
- 打开 NDVI 赋能分析可见四段，而不是三项护栏。
- L0 示例（如架次质检）应用段不得写成飞行合格证；L3 示例不得写成处方。
- 赋能效果对照仍可运行；未配置密钥时的回退行为不变。
- `tests/test_l3_aide.py` 与前端 `npm run build` 通过。
