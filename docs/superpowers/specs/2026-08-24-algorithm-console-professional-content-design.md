# 高光谱算法控制台专业内容改版设计

**日期：** 2026-08-24  
**状态：** 待用户审阅  
**范围：** `algorithm/web` 与控制台算法元数据，覆盖全部 45 个算法  

## 1. 改版目标

将算法控制台从“可运行的算法目录”提升为兼顾领导汇报、专业评审和学习培训的高光谱算法知识与演示平台。

页面采用“领导摘要 + 专家详解”的渐进式结构：

- 首屏快速回答算法是什么、解决什么问题、产生什么业务价值。
- 向下展开后给出物理或数学依据、公式、参数、限制和工程差异。
- 运行演示说明真实输入、处理过程、输出用途和使用边界。
- 表单字段逐项解释作用、单位、范围、默认值、调参影响和误配风险。
- 所有内容以本仓库真实实现为准，明确区分“当前实现”与“业界完整做法”。

## 2. 目标读者

### 2.1 领导与业务负责人

主要关心：

- 算法解决什么业务问题。
- 位于高光谱生产链哪个环节。
- 输入什么、输出什么。
- 结果能支持什么判断或决策。
- 当前能力是否达到生产应用要求。

### 2.2 遥感、高光谱与算法专业人员

主要关心：

- 数据前提、物理依据和数学方法是否准确。
- 参数含义、单位、范围和敏感性。
- 结果如何解释，误差和不确定性来自哪里。
- 当前代码实现相对标准方法做了哪些简化。

### 2.3 学习与实施人员

主要关心：

- 如何准备输入数据。
- 如何填写参数。
- 如何判断结果是否合理。
- 常见错误如何识别和处理。

## 3. 信息架构

算法页继续保留三个一级 Tab：

1. 算法原理
2. 运行演示
3. 产品分析

本次重点改造前两个 Tab。页面不增加“领导版/专家版”开关，避免维护两套重复内容；通过首屏摘要、分节内容和可展开的专业细节实现渐进式阅读。

## 4. 算法原理页

### 4.1 首屏摘要

首屏控制在一屏内，展示：

- 一句话定义：说明算法的本质，不使用空泛宣传语。
- 核心价值：说明它在生产链中解决的具体问题。
- 所处环节：标明 L0 前、L0、L0→L1、L1→L2、L2、L3、L3→L4 或 L4。
- 关键输入与主要输出。
- 方法标签与关键限制。

### 4.2 专家详解

每个算法统一包含以下章节：

1. **问题背景**：为什么需要该算法，上游数据通常存在哪些问题。
2. **原理依据**：说明物理、光谱、几何、统计或机器学习依据。
3. **核心公式**：给出公式并逐项解释符号、单位和合理范围。
4. **数据前提**：说明数据级别、波段、定标、坐标系、尺寸对齐、标签或模型要求。
5. **计算流程**：逐步写清每一步的输入、处理、输出及这样处理的原因。
6. **参数敏感性**：解释关键参数增大、减小或选错时的结果变化。
7. **结果解读**：说明输出值、颜色、类别、图层或统计指标代表什么。
8. **适用条件**：明确推荐使用的数据与业务条件。
9. **不适用条件**：明确不能直接使用或结果不可靠的情况。
10. **误差与风险**：列出主要误差来源、传播关系和质量检查方法。
11. **实现边界**：区分本仓库实现、教学简化和业界生产方案。
12. **上下游关系**：说明依赖哪些前置算法，结果供哪些后续算法使用。
13. **参考来源**：保留论文、标准或权威资料，并标注当前实现采用的方法。

### 4.3 公式表达

- 公式保持专业符号，同时配套中文解释。
- 每个变量说明物理意义、单位、数据来源和合理范围。
- 对波段指数同时给出波段名称与典型波长范围。
- 明确波段索引与波长不是同一个概念。
- 同名异义指标必须注明版本，例如 Gao NDWI 与 McFeeters NDWI。
- 无法由当前实现严格支撑的理论能力不得写成已实现功能。

### 4.4 原理示意

保留现有交互示意，并补充：

- 图示阅读提示。
- 横纵轴、颜色和符号说明。
- 用户操作会改变什么。
- 图示用于解释什么，不代表什么。
- 对算法不确定性或失效情况给出视觉提示。

## 5. 运行演示页

### 5.1 功能说明

不再由 `purpose + method + HTTP 接口` 自动拼成一句话。每个算法提供结构化内容：

- **功能定位**：该功能在当前生产环节承担什么职责。
- **处理对象**：输入数据是什么状态，存在哪些待解决问题。
- **处理变化**：执行前后数据发生哪些变化。
- **主要产物**：输出文件、图层、报表或模型指标。
- **业务价值**：输出可支持哪些判断、筛查或决策。
- **演示重点**：用户运行示例时应重点观察什么。
- **使用前提**：运行前必须满足的数据条件。

### 5.2 适用场景

每个算法按以下维度说明：

- 典型行业或作业场景。
- 适用对象，例如农田、林地、水体、实验室样品或工业材料。
- 推荐传感器、波段、空间分辨率和数据级别。
- 能回答的业务问题。
- 不建议使用的场景及原因。
- 与上游和下游算法的组合方式。

### 5.3 演示流程提示

表单上方显示四步流程：

1. 选择示例数据或上传自有数据。
2. 检查数据条件与字段要求。
3. 设置参数并执行。
4. 解读输出与质量指标。

示例数据模式明确提示：示例默认参数只适用于示例文件，不可直接照搬到其他传感器数据。

## 6. 表单字段说明

### 6.1 字段数据结构

输入字段元数据从当前的简单结构扩展为：

- `name`：完整接口字段名。
- `label`：专业、清晰的中文名称。
- `type`：接口数据类型。
- `required`：是否必填。
- `format`：文件或数据格式。
- `description`：字段作用。
- `unit`：单位，无量纲时明确标注。
- `default`：默认值。
- `defaultReason`：默认值依据。
- `range`：合法范围或候选值。
- `selectionGuide`：如何根据传感器、数据和业务选择。
- `effect`：参数变化对结果的影响。
- `risk`：错误配置的后果。
- `example`：示例值。
- `vis`：可视化方式。

输出字段补充：

- 输出内容与数据结构。
- 数值单位或类别含义。
- 合理范围。
- 可视化方式。
- 结果解读方法。
- 质量检查方法。
- 下游用途。

### 6.2 字段展示

表单字段默认显示：

- 中文名称、接口键名、类型、必填状态。
- 一至两句字段作用。
- 单位、范围和示例默认值。

“详细说明”展开后显示：

- 默认值依据。
- 选择方法。
- 调参影响。
- 误配风险。
- 与其他字段的约束关系。

### 6.3 波段字段专项规则

`red_band`、`nir_band`、`re_band`、`blue_band`、`green_band`、`swir_band` 等字段必须说明：

- 值是从 0 开始的波段数组索引，不是纳米波长。
- 推荐波长区间。
- 应优先读取影像波长元数据后选择最近波段。
- 示例默认索引只适用于示例数据。
- 选错波段对公式结果的方向性影响。

例如 `red_band`：

> 指定红光反射率在影像波段数组中的位置，索引从 0 开始。应根据影像波长元数据选择约 620–680 nm 的红光波段，不能直接填写 660。示例默认值只对应内置示例立方体。若误选红边或近红外波段，NDVI 的物理意义和数值分布将发生明显偏差。

## 7. 内容数据组织

### 7.1 单一事实来源

- 运行字段、默认值和输出键以 Python 服务实现及 testdata 为准。
- 算法方法名和接口地址继续由后端控制台元数据提供。
- 专业解释使用结构化内容文件，不在 Vue 模板中拼接长句。
- 原理内容与运行字段共享术语和参数解释，避免同一字段两套说法。

### 7.2 文件边界

避免把 45 套内容放进单个超大文件：

- 按 L0、L1、L2、L3/L4 或现有业务层级拆分原理内容。
- 参数知识库按通用参数和算法专属参数拆分。
- Vue 组件只负责展示，不承载专业事实。
- 通用术语、单位、风险提示和波段说明集中复用。

### 7.3 内容来源优先级

1. 当前 `service.py` 真实计算逻辑和参数读取。
2. 测试数据 `params.json` 与实际文件结构。
3. `采集到算法-算法清单.md`。
4. 原始论文、行业标准和官方算法说明。
5. 通用教材或工程经验。

若来源之间不一致，以真实实现为当前能力，并在“实现边界”中解释差异。

## 8. 视觉与交互

- Tab 保持轻量导航样式，避免浏览器默认蓝色焦点框主导视觉；键盘焦点仍需清晰且符合无障碍要求。
- 正文采用适合长文阅读的行宽、字号和行距。
- 首屏摘要使用少量重点卡片，不将所有内容做成同权重卡片。
- 专家内容按章节分组，低频细节使用原生可访问的展开组件。
- 参数帮助文字提高字号、对比度和段落层次。
- 单位、范围、默认值使用紧凑标签；风险提示使用克制的警示色。
- 手机和窄屏改为单列，表格避免横向溢出。

## 9. 内容质量标准

每个算法页面必须满足：

- 不使用“高效、精准、先进”等无证据形容词替代技术说明。
- 不把相关性表述为因果关系。
- 不把示例阈值写成通用行业阈值。
- 不把分类精度、反演精度写成固定性能。
- 明确输入是 DN、辐亮度还是反射率。
- 明确波段索引起点、单位和坐标约定。
- 明确必填与代码层面可选之间的区别。
- 明确输出的数值范围、无效值和背景值。
- 明确当前实现的简化、限制和风险。
- 中文表达专业、短句优先，首次出现缩写给出中英文全称。

## 10. 验收标准

### 10.1 覆盖性

- 45 个算法均有完整的原理、运行说明、场景说明和字段说明。
- 所有真实表单字段均能在专业元数据中找到。
- 所有输出字段均有解读和质量检查说明。

### 10.2 准确性

- 字段名、类型、默认值与后端运行接口一致。
- 公式与代码实现一致。
- 输入输出文件和可视化类型与真实运行结果一致。
- 本仓库未实现的能力明确标注为标准做法或扩展建议。

### 10.3 可读性

- 领导在首屏可以快速理解算法价值和当前能力。
- 专业人员可以找到数据前提、公式变量、参数范围、风险和实现边界。
- 初学者可以根据说明完成示例运行，并知道如何判断结果是否合理。

### 10.4 功能验证

- TypeScript 类型检查通过。
- 45 个算法详情接口均能返回扩展后的元数据。
- 所有算法页面均可正常切换三个 Tab。
- 示例数据加载、参数修改、算法执行和结果展示不受改版影响。
- 使用代表性算法验证不同类别：航线规划、辐射校正、NDVI、传统分类、深度学习、异常检测、地块统计。

## 11. 实施边界

本次改版包括：

- 45 个算法的专业内容扩充。
- 原理页和运行页的信息架构优化。
- 表单字段结构与展示优化。
- 相关样式、类型和元数据接口调整。

本次不包括：

- 修改算法数学实现以达到生产级精度。
- 新增模型训练数据或重新训练模型。
- 改变现有 API 路径和主要运行协议。
- 重做产品分析 Tab。
