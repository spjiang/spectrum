# 高光谱算法能力汇报 Word 设计

## 目标

将以下三份文档整合为一份面向领导汇报、兼顾技术查阅的正式 Word：

- `algorithm/docs/采集到算法-算法清单.md`
- `algorithm/docs/当前服务简单介绍.md`
- `algorithm/docs/算法API测试清单.md`

核心要求：完整列出 45 项算法，为每项提供相对详细且易懂的用途说明，并补充统一封装策略、真实服务截图和架构示意图。

## 交付物

- 主文档：`algorithm/docs/高光谱45项算法能力与服务封装方案.docx`
- 配套图片：`algorithm/docs/word-assets/`
- 可复现生成脚本：`algorithm/docs/build_algorithm_word.py`

1. 封面与版本信息

3. L0–L4 数据产品体系与处理链

## 单项算法模板

每项至少包含：

- 编号、中文名、算法 ID、所属层级、当前状态
- 一句话用途
- 解决的问题
- 原理/处理逻辑（非公式化、领导可理解）
- 典型业务场景
- 输入数据
- 输出结果
- 当前服务封装方式
- 生产化建议或限制

可运行项说明真实实现及产物；骨架项必须明确标注“接口已预留，核心算法待生产化实现”，不得将 HTTP 200 描述成算法能力已完成。

## 封装策略

采用“统一网关 + 标准契约 + 算法适配器 + 任务治理”的分层方案：

1. API 层：FastAPI、统一 `/api/v1/{algorithm_id}/run|health`
2. 契约层：`file`、`file2`、`params` 输入；统一 JSON 响应
3. 适配层：一算法一目录，`service.py` 屏蔽底层实现差异
4. 数据层：GeoTIFF、ENVI、GeoJSON、CSV；统一临时目录和产物目录
5. 执行层：轻任务同步，重任务异步队列；GPU/CPU 资源标签
6. 治理层：鉴权、限流、审计、超时、日志、指标、版本
7. 交付层：原始算法结果转为专题图、统计表、地块 JSON 和告警

生产化路线按“现有 12 项加固 → L2/L3 高频算法补齐 → L0/L1 厂商能力接入 → L4 业务闭环”推进。

## 排版

- A4 纵向，中文正式报告风格
- 标题层级、页眉页脚、页码、自动目录
- 总表使用横向页面或紧凑字号
- 45 项逐项说明按 L0–L4 分组，每项保持一致版式
- 可运行/骨架使用文字标签并配合克制的颜色区分
- 图片含编号、标题和来源说明

## 数据一致性

- 算法名称、编号、层级、输入输出以算法清单为准
- algorithm_id、接口参数、测试状态以 API 测试清单为准
- 服务架构以当前服务说明和源码为准
- 对冲突状态采用时间更新的测试清单，并在执行摘要说明：
  `当前服务简单介绍.md` 的 11/34 已过期，最新为 12/33

## 验收标准

- Word 可正常打开，无缺图、乱码、表格越界
- 45 项算法编号连续且无遗漏、无重复
- 每项均有用途、场景、输入、输出、状态和封装建议
- 骨架项与可运行项不混淆
- 至少包含 2 张架构图和 3 张真实服务/产物截图
- 封装策略具备生产化分层、非单纯复述现有服务
- 生成脚本可重复执行并产出同名 Word
