# LUMIR Skill 配置说明

本文说明如何配置 DeepSeek、知识库与流水线参数，以便本地测试与复现。

## 1. 目录与副本

| 路径 | 用途 |
|------|------|
| `.cursor/skills/lumir-spectral-agent/` | **自包含 Skill（可整包 zip 分发）** |
| `LUMIR-an-LLM/docs/skill-dev/lumir-spectral-agent/` | 文档树副本（保持同步） |

内嵌资源：`knowledge_base/structured_papers1.json`、`data/`、`Papers/`。详见 [PORTABLE.md](PORTABLE.md)。

Skill 内关键配置文件：

| 文件 | 说明 |
|------|------|
| `config.example.yaml` | 配置模板（入库） |
| `config.yaml` | 本地配置（gitignore，勿提交密钥） |
| `.env.example` | 环境变量模板 |
| `.env` | 本地环境变量（gitignore） |
| `knowledge_base/README.md` | 知识库字段与追加说明 |
| `knowledge_base/extra_papers.example.json` | 追加库模板（非正式库） |

## 2. 快速配置（DeepSeek）

```bash
# 进入主副本（任选一处）
cd LUMIR-an-LLM/docs/skill-dev/lumir-spectral-agent

cp config.example.yaml config.yaml
cp .env.example .env
# 编辑 .env，填写真实 Key
```

`.env` 示例：

```bash
LUMIR_API_KEY=sk-你的DeepSeek密钥
LUMIR_BASE_URL=https://api.deepseek.com
LUMIR_MODEL=deepseek-chat
```

也可用环境变量（优先级通常高于仅写在 yaml 里的说明）：

```bash
export LUMIR_API_KEY=sk-...
export LUMIR_BASE_URL=https://api.deepseek.com
export LUMIR_MODEL=deepseek-chat
```

兼容读取顺序（`api_key_env`）：`LUMIR_API_KEY` → `DEEPSEEK_API_KEY` → `OPENAI_API_KEY`。

**不要把真实 API Key 写入仓库或提交到 git。**

## 3. config.yaml 字段说明

### 3.1 `llm`

| 字段 | 默认 | 含义 |
|------|------|------|
| `api_key_env` | 见 example | 从哪些环境变量读 Key |
| `base_url` | `https://api.deepseek.com` | OpenAI 兼容接口地址 |
| `model` | `deepseek-chat` | 模型名 |
| `temperature_entity` | `0.1` | 步骤1 实体抽取温度 |
| `temperature_method` | `0.1` | 步骤3 方法映射温度 |
| `temperature_infer` | `0.5` | 步骤5 few-shot 推理温度 |

换模型时改 `base_url` + `model`，并保证 Key 对应该服务商。

### 3.2 `knowledge_base`

| 字段 | 默认 | 含义 |
|------|------|------|
| `primary` | `auto` | 主知识库。`auto` = 自动定位源码下 `structured_papers1.json` |
| `extra` | `./knowledge_base/extra_papers.json` | 可选追加库；文件不存在则忽略 |
| `top_k` | `2` | BM25 返回文献条数 |

**测试阶段请继续用主库 `structured_papers1.json`，不必自建。**

何时需要 `extra_papers.json`：

- 新材料在主库搜不到相近 `research_object`
- 需要覆盖/补充某材料的预处理与特征描述

创建方式：

```bash
cp knowledge_base/extra_papers.example.json knowledge_base/extra_papers.json
# 按真实文献改字段，不要保留示例里的 my custom material
```

单条必填字段：`paper_name`、`research_object`、`preprocessing_method`、`feature_extracting_method`。

### 3.3 `pipeline`

| 字段 | 默认 | 含义 |
|------|------|------|
| `skip_method_llm` | `false` | `true` 时步骤3 跳过 LLM，改用论文 Table4 |
| `few_shot` | `8` | few-shot 示例条数 |
| `test_ratio` | `0.2` | 测试集比例 |
| `max_test_samples` | `16` | 测试样本上限（控费用/上下文） |
| `random_seed` | `42` | 划分随机种子 |

### 3.4 `datasets`

| 字段 | 默认 | 含义 |
|------|------|------|
| `default` | `chenpi` | 未传 `--dataset` 时的默认集 |

可选数据集名：`chenpi`、`milk`、`cn_medicine`、`corn`、`tecator`。

## 4. 知识库与 Papers 目录的关系

| 资源 | 是否必须 | 作用 |
|------|----------|------|
| `structured_papers1.json` | **是** | BM25 检索用的结构化知识库 |
| `knowledge_base/extra_papers.json` | 否 | 追加文献 |
| `Papers/md/`（源码树下） | 否 | 文献溯源（题录/OA 全文），**E2E 不读该目录** |

结论：正常测试只需主库 JSON + LLM Key；不必把 `Papers` 同步进 Skill，也不必把 example 当成正式追加库。

## 5. 依赖环境

建议 Python 3.10+。E2E 常用包：

```bash
pip install numpy scipy scikit-learn rank_bm25 openai pyyaml certifi pypdf
```

- 完整 E2E 需要网络访问 DeepSeek API  
- 离线冒烟可用 `scripts/demo_pipeline.py --offline`（不调 LLM）  
- 可不装 CUDA / torch

## 6. 配置自检

```bash
# 1) 配置文件存在
ls config.yaml   # 或使用默认 config.example.yaml

# 2) Key 可读
python -c "import os; print('KEY', 'OK' if os.getenv('LUMIR_API_KEY') or os.getenv('DEEPSEEK_API_KEY') else 'MISSING')"

# 3) 主库可解析（auto）
python scripts/run_e2e.py --dataset chenpi --stop-after retrieve
```

若提示未找到 API Key：检查 `.env` 是否在 Skill 根目录，或是否已 `export`。

## 7. 双副本同步建议

改配置模板或文档后，将主副本同步到 Cursor 副本：

```bash
rsync -a --delete \
  --exclude 'runs/*' --exclude 'config.yaml' --exclude '.env' \
  --exclude 'knowledge_base/extra_papers.json' \
  LUMIR-an-LLM/docs/skill-dev/lumir-spectral-agent/ \
  .cursor/skills/lumir-spectral-agent/
```

本地密钥文件不要同步进 git。
