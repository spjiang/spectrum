# LUMIR 演示说明

面向汇报 / 现场演示：讲什么、点哪里、跑哪条命令、屏幕上会出现什么。  
配置细节见 [配置说明.md](配置说明.md)。

---

## 一、一句话开场

> LUMIR 用大模型当“调度大脑”：先读懂你的光谱分析意图，再检索文献知识库选预处理/特征方法，本地算特征，最后用少量示例做分类或回归——**不把原始高维光谱整段塞进大模型**。

默认演示模型：**DeepSeek**（`deepseek-chat`）。

## 三、建议演示节奏（约 8–12 分钟）

| 时段 | 讲什么 | 跑什么 |
|------|--------|--------|
| 1 min | 背景：光谱难、标注少；LUMIR = 文献引导 + few-shot | 不跑 |
| 2 min | 五步流水线（见下节） | 指着流程图讲 |
| 2 min | **无 Key 也能看**：检索 + 特征 + 本地对照 | 演示 A（离线） |
| 4 min | **完整链路**：实体 → 检索 → 方法 → 特征 → LLM 推理 | 演示 B（陈皮分类） |
| 2 min | 换任务类型：回归看含量 | 演示 C（玉米蛋白） |
| 1 min | 打开 `runs/*.json` 看结构化结果 | 收尾 |

网络不稳时：只做演示 A + 提前准备好的 `runs` 报告截图。

## 四、给观众讲的五步（对照屏幕输出）

```text
自然语言问题 + 光谱
        │
        ▼
[1] LLM 实体抽取     → 研究对象、任务类型（分类/回归/异常）
        │
        ▼
[2] BM25 查知识库    → 相关文献里的预处理 / 特征描述
        │                （主库 structured_papers1.json，约 129 条）
        ▼
[3] LLM 方法映射     → 映射成代码函数名，再投票选定
        │
        ▼
[4] 本地化学计量学   → SNV/SG/PCA/PLS 等，得到低维特征
        │
        ▼
[5] LLM few-shot     → 类别标签 或 连续数值（COD/蛋白/脂肪等）
```

讲解抓手：

- **知识库**是结构化 JSON，不是必须打开 `Papers/md` 全文  
- **步骤 2、4 不是 LLM**；LLM 主要在 1 / 3 / 5  
- 输出给人看的是：**标签或指标**，不是原始光谱向量

## 五、现场命令（复制即用）

### 演示 A：离线暖场（不耗 API）

**讲解词：**  
“先不连大模型：看知识库怎么选方法、光谱怎么压成特征；随机森林只是对照，证明特征已经能用。”

```bash
python $SKILL/scripts/demo_pipeline.py --dataset chenpi --offline
```

**屏幕上应出现：**

1. 研究对象 ≈ Citri Reticulatae Pericarpium，任务 = classification  
2. BM25 命中陈皮相关文献  
3. 方法如 SNV → PCA，特征 shape 如 `(8, 30, 5)`  
4. 本地基线 Acc（对照用，不是论文 LLM 结果）

可再补一句牛奶/玉米：

```bash
python $SKILL/scripts/demo_pipeline.py --dataset milk --offline
python $SKILL/scripts/demo_pipeline.py --dataset corn --offline
```

---

### 演示 B：主秀——陈皮分类（完整 E2E）

**讲解词：**  
“输入一句人话：要对陈皮光谱做分类。DeepSeek 抽出实体，知识库给出文献方法，本地算出 PCA 特征，再用少量样本让大模型投票年份/类别。”

```bash
python $SKILL/scripts/run_e2e.py --dataset chenpi
```

**逐步指给观众看：**

| 输出段 | 一句话解释 |
|--------|------------|
| `[1] LLM 实体抽取` | 听懂“陈皮 + 分类” |
| `[2] BM25 知识库检索` | 从约 129 篇结构化文献里找相近材料 |
| `[3] 方法映射` | 文献说法 → 可执行函数（或 Table4 回退） |
| `[4] 预处理 + 特征` | 高维光谱 → 低维特征 |
| `[5] LLM few-shot` | 给出 Acc 等指标 |
| `报告已写入 runs/...` | 可打开 JSON 给应用/归档 |

省时间 / 省费用的半程演示：

```bash
# 只演示到检索（强调知识库）
python $SKILL/scripts/run_e2e.py --dataset chenpi --stop-after retrieve

# 演示到特征（强调不把原光谱塞给 LLM）
python $SKILL/scripts/run_e2e.py --dataset chenpi --stop-after features
```

### 演示 C：回归——玉米蛋白（换任务类型）

**讲解词：**  
“分类输出的是类别；回归输出的是连续含量。同一套智能体，换问题即可。”

```bash
python $SKILL/scripts/run_e2e.py --dataset corn
```

**期望：** `task_type=regression`，特征侧常见 SNV+PLS，指标含 R² / RMSE。

## 六、演示后展示报告

报告目录：`$SKILL/runs/e2e_<数据集>_<时间>.json`

建议打开给观众看的字段：

- `question`：自然语言问题  
- `steps.entity`：抽到的对象与任务  
- `steps.retrieve.matched`：命中的文献标题与方法描述  
- `steps.methods.selected`：最终选用的预处理/特征  
- `steps.features.feature_shapes`：特征维度  
- `steps.infer.metrics`：Acc 或 R²  

**话术：**  
“应用端最终可消费的就是这类结构化结果：材料、任务、方法、指标——而不是原始光谱矩阵。”

## 七、演示话术备忘（Q&A）

| 可能提问 | 简短回答 |
|----------|----------|
| 和传统 CNN/PLS 比？ | 少标注、少调参；靠提示与文献方法；小样本场景更灵活 |
| 必须自建知识库吗？ | 测试/演示用现成 `structured_papers1.json` 即可 |
| Papers 目录要同步吗？ | 不用；那是溯源，流水线读的是 JSON 字段 |
| 异常检测呢？ | 框架支持；当前演示入口以分类/回归为主 |
| API 挂了怎么办？ | 改演示 A 离线 + 展示历史 `runs` 报告 |
