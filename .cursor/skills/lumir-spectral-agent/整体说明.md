# LUMIR Spectral Agent — 整体说明

本 Skill（`lumir-spectral-agent`）把中山大学 LUMIR（LLM-driven Unified agent for Multi-task Infrared spectroscopy Reasoning）论文流水线工程化为**可自包含分发**的 Cursor / Agent Skill：内嵌知识库与演示数据，用 DeepSeek（OpenAI 兼容 API）跑端到端，也可纯离线冒烟。

- **Agent 生产规程入口**：[SKILL.md](SKILL.md)（强制约束 + 执行/交付规范；对话里 `@SKILL.md` / 提及 LUMIR）
- **本文作用**：总览「是什么、目录干什么、谁在跑、文档怎么查」
- **便携分发**：[PORTABLE.md](PORTABLE.md)

---

## 1. 它做什么

对齐论文五步流水线：

```text
1. LLM 实体抽取（研究对象 + 任务类型）
2. BM25 检索结构化文献知识库 → 预处理 / 特征方法描述
3. LLM 将文献方法名映射为代码函数名，再多数投票（可跳过）
4. 本地化学计量学：预处理 + 特征提取（不调 LLM）
5. LLM few-shot：分类 / 回归 / 异常检测（只吃低维特征，不吃原始高维光谱）
```

约束原则：**禁止把完整原始高维光谱直接塞给 LLM**。

## 2. 两层结构（先读这张表）

| 层级 | 路径 | 是否参与默认运行 | 作用 |
|------|------|------------------|------|
| 工程层（推荐） | `scripts/` + `knowledge_base/` + `data/` + 配置 | **是** | 日常演示、E2E、报告输出 |
| 对照层 | `vendor/LLM-Agent-for-Automated-Infrared-Spectral-Reasoning-main/` | **否** | 论文原仓库源码副本，阅读 / 对照用 |
| 溯源层 | `Papers/` | 否（E2E 不读） | 结构化库里 `paper_url` 对应的 md / 元数据 |
| 产出层 | `runs/` | 写出 | `e2e_*.json` 等运行报告 |

删掉 `vendor/` 或 `Papers/` **不影响** `demo_pipeline` / `run_e2e` 正常跑通；删掉 `knowledge_base/` 或 `data/` 则会失败。

## 4. 各目录详细作用

### 4.1 `scripts/` — 真正在跑的代码

| 文件 | 作用 | 是否需要 API Key |
|------|------|------------------|
| `demo_pipeline.py` | 冒烟 / 演示：检索 + 固定方法 + 本地预处理特征；`--offline` 不调 LLM | 离线模式：否 |
| `run_e2e.py` | 五步 E2E；支持 `--skip-method-llm`、`--stop-after features` | 完整跑：是 |

路径解析优先使用 Skill 根下的 `knowledge_base/` + `data/`（自包含）。仅当内嵌资源缺失时，才回退到仓库旁旧布局路径（兼容开发机，不是依赖 `vendor/`）。

### 4.2 `knowledge_base/` — 文献方法知识

- BM25 按「研究对象」等检索，返回文献中的预处理 / 特征方法描述。
- `primary: auto`（见 config）时自动用内嵌 `structured_papers1.json`。
- 新材料搜不到时，按模板追加 `extra_papers.json`（勿轻易改主库）。

### 4.3 `data/` — 演示光谱

供 `chenpi` / `milk` / `corn` 等内置数据集加载。体积小，**分发时必带**。

### 4.4 `Papers/` — 文献溯源（可选）

方便人工打开 md、核对 DOI / 摘要；**E2E 脚本运行时不读取**。只要流水线、要瘦包：可删后再 zip（约剩 5–6MB）。

### 4.5 `vendor/` — 原论文源码副本

| 有什么用 | 没什么用 |
|----------|----------|
| 对照论文模块实现与 Prompt | 不是 Skill 默认入口 |
| 整包带走时仍有完整出处 | 日常演示不必执行其中 `.py` |
| 读 `main.ipynb` 理解原始流程 | 依赖更重（nltk 等），路径可能写死 |

`data/` / `Papers/` **没有**再拷进 vendor（避免体积翻倍）。若要在 vendor 内按原相对路径找数据，见 [vendor/README.md](vendor/README.md)。

### 4.6 `runs/` — 运行报告

`run_e2e.py` 写出 JSON：含 entity / retrieve / methods / features / infer 等字段，便于演示展示与排障。本地产物，分发 zip 时可排除。

### 4.7 配置与密钥

| 文件 | 作用 |
|------|------|
| `.env` / 环境变量 | `LUMIR_API_KEY`（或 `DEEPSEEK_API_KEY`）、可选 `LUMIR_BASE_URL` / `LUMIR_MODEL` |
| `config.yaml` | temperature、few-shot、知识库路径等 |
| `*.example*` | 可提交的模板；复制后改本地文件 |

**切勿**把真实 Key 写进仓库或打进对外 zip。

## 6. 快速上手

```bash
cd .cursor/skills/lumir-spectral-agent   # 或 skill-dev 同步副本
pip install -r requirements.txt

# 离线冒烟（无 Key）
python scripts/demo_pipeline.py --dataset chenpi --offline

# 完整 E2E（需 Key）
cp .env.example .env          # 填写 LUMIR_API_KEY
cp config.example.yaml config.yaml
python scripts/run_e2e.py --dataset chenpi
# 报告：runs/e2e_chenpi_*.json
```

对话中：`@SKILL.md` 或自然语言提及 LUMIR / 红外光谱智能体。

## 8. 体积与分发建议

| 内容 | 约 | 建议 |
|------|-----|------|
| 全量（含 Papers） | ~50MB | 需要文献溯源时 |
| 去 Papers | ~5–6MB | 只跑流水线 |
| 去 vendor | 再减 ~0.35MB | 不需要原码对照时 |
| 必保留 | `scripts/` + `knowledge_base/` + `data/` + 文档与 example 配置 | 否则无法自包含运行 |

分发 zip 排除：`.env`、`config.yaml`、`runs/*`。
