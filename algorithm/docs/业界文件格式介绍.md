# 业界文件格式介绍

高光谱从采集到业务交付，各环节交换的不是「内存里的数组」，而是**带元数据、可跨软件互操作的标准文件**。本文介绍农情/遥感业务中常用的文件格式：是什么、何时用、与 L0–L4 的对应关系，以及本仓库服务如何使用它们。

> 说明：`.npy` 仅适合教学与算法实验，**不是**业界业务对接主格式。

---

## 一、为什么需要标准格式

| 需求 | 标准格式解决什么 |
|------|------------------|
| 上地图 | 带地理坐标，可叠地块、量面积 |
| 跨软件 | ENVI / QGIS / ArcGIS / 业务系统可互通 |
| 可追溯 | 波段波长、坐标系、单位等写在元数据里 |
| 可对接 | HTTP/API、GIS、大屏按同一契约交换 |

一句话：**格式选对，处理中心、算法服务、业务系统才能接力，而不是各自转一遍「私有二进制」。**

---

## 二、常用格式一览

| 类型 | 格式 | 常见扩展名 | 典型用途 |
|------|------|------------|----------|
| 栅格立方体 / 专题图 | **GeoTIFF** | `.tif` / `.tiff` | L2 反射率、指数图、分类图、DEM |
| 高光谱归档 | **ENVI** | `.hdr` + `.dat` / `.img` | 处理中心存量数据、科研流水线 |
| 地块 / AOI / 斑块 | **GeoJSON** | `.geojson` / `.json` | 测区、标注、田块边界、检测斑块 |
| 矢量（传统 GIS） | **Shapefile** | `.shp` + `.dbf` 等 | 地块库、专题斑块（业务侧常见） |
| POS / 轨迹 | **CSV** | `.csv` | GPS/IMU 时间序列、采样点属性 |
| 光谱库 / 端元 | **CSV** | `.csv` | 实验室光谱、端元表 |
| 业务报表 | **JSON** | `.json` | 面积统计、精度指标、告警列表、API |
| 厂商原始 | **Raw / 专用** | 因相机而异 | L0 原始帧（进管线前需厂商工具或预处理） |

## 三、逐项介绍

### 1. GeoTIFF（业界栅格主格式）

**是什么**  
在 TIFF 上扩展地理参考（坐标系、仿射变换/投影），可存单波段或多波段。高光谱常把「高 × 宽 × 波段」写成多波段 GeoTIFF。

**何时用**  
- L2：反射率正射立方体（算法最常见输入）  
- L3：NDVI/分类等专题图（算法最常见输出）  
- DEM、掩膜等辅助栅格  

**优点**  
GIS/遥感软件广泛支持；一个文件可同时带影像与坐标；便于 HTTP 上传下载。

**注意**  
波段顺序、波长、反射率/辐亮度单位等建议在元数据或伴随说明中写清，避免「有图不知哪一波段」。用 QGIS 打开本仓库 `.tif`、查看像元值并导出 CSV，见 [QGIS打开GeoTIFF与导出操作手册.md](./QGIS打开GeoTIFF与导出操作手册.md)。

---

### 2. ENVI（高光谱处理中心常见归档）

**是什么**  
`.hdr`（ASCII 头：行列、波段数、波长、交错方式等）+ `.dat`/`.img`（二进制影像）。ENVI、许多科研脚本默认读写此格式。

**何时用**  
处理中心归档、历史项目交接、与 ENVI 工作流对接。

**与 GeoTIFF 关系**  
业务交换、Web/API 更倾向 GeoTIFF；科研/处理中心内部仍大量使用 ENVI。本服务**可读 ENVI**，正式对外产物优先 **GeoTIFF**。

---

### 3. GeoJSON（矢量交换首选之一）

**是什么**  
基于 JSON 的地理要素格式，可表达点、线、面及属性（地块编号、作物名等）。

**何时用**  
- 测区范围、AOI 裁剪  
- 田块边界（分区统计输入）  
- 检测/分割输出的斑块轮廓  

**优点**  
文本可读、与 Web/API 天然契合；QGIS 等可直接打开。

**对照**  
存量地块库多为 **Shapefile**；对接时常见「shp → GeoJSON」再进服务。

---

### 4. Shapefile（传统 GIS 地块库）

**是什么**  
多文件组合（`.shp` / `.shx` / `.dbf` / `.prj` 等），长期作为行业地块与专题矢量标准之一。

**何时用**  
政务/农经地块库、历史专题图斑；最终制图交付有时仍要求 shp。

**注意**  
本教学 API 样例以 **GeoJSON** 为主；生产对接 shp 时在业务侧或网关做格式转换即可。

---

### 5. CSV（表格型辅助数据）

**是什么**  
逗号分隔文本表，列含义由表头约定。

**典型用法**  

| 场景 | 常见列（示例） |
|------|----------------|
| POS / 轨迹 | 时间、经度、纬度、高程、俯仰、横滚、航向 |
| 光谱库 / 端元 | 波长、反射率，或端元名 + 各波段值 |
| 样点属性 | 样点 ID、类别标签、化验值（叶绿素、氮等） |

**优点**  
简单、Excel 可编、脚本友好。  
**注意**  
时间与坐标系单位要在项目内统一（如 WGS84、UTC）。

---

### 6. JSON（业务结果与 API 载荷）

**是什么**  
结构化文本，适合报表、配置与 HTTP 响应体。

**何时用**  
- L4：地块面积表、类别占比、告警列表  
- API：`success` / `data` / `files`（产物路径）  
- 算法参数：`params` 字段中的 JSON 字符串  

**与 GeoJSON 区别**  
普通 JSON 报表**不一定**含几何；GeoJSON 是「带几何的 JSON」。

---

### 7. 厂商 Raw / 专用格式（L0）

**是什么**  
相机厂商原始帧、专用封装或私有头，常伴随 POS、曝光日志。

**何时用**  
仅在采集与传感器级预处理阶段；进入标准分析前，一般由厂商工具或处理中心转为辐亮度/ENVI/GeoTIFF。

**本服务**  
不以厂商 raw 为正式输入契约；联调从 **L2 类 GeoTIFF** 起步更合适。

---

## 四、与 L0–L4 的对应关系

```text
L0  厂商 raw / 专用帧 + POS 日志
      ↓ 预处理（定标、正射、镶嵌等）
L1  辐亮度条带（常仍为 ENVI / 中间产品）
      ↓ 反射率 + 几何产品化
L2  GeoTIFF / ENVI 反射率正射立方体   ← 算法服务主要输入
      ↓ 指数 / 分类 / 反演
L3  GeoTIFF 专题图（指数、分类、参数） ← 算法服务主要输出
      ↓ 按地块汇总
L4  GeoJSON/shp 地块 + JSON 报表/告警   ← 业务系统交付
```

两条常用业务链的文件形态：

| 链路 | 典型输入 | 典型输出 |
|------|----------|----------|
| 作物分类 | L2 GeoTIFF + 标签/样点 | 分类 GeoTIFF → 地块 JSON 面积表 |
| 长势监测 | L2 GeoTIFF | NDVI 等 GeoTIFF → 地块均值 JSON + 告警 |

## 五、本仓库服务中的用法

| 项 | 约定 |
|----|------|
| 上传 | `multipart`：`file` / `file2`，按扩展名解析 |
| 栅格主格式 | **GeoTIFF**（`.tif`） |
| 矢量样例 | **GeoJSON** |
| 表格 | **CSV**（POS、光谱库等） |
| 返回 | JSON；栅格产物路径在 `files` 中，扩展名优先 **`.tif`** |
| `.npy` | 仅兼容旧实验数据，**不作为正式契约** |

联调样例与 curl 清单见：[算法API测试清单.md](./算法API测试清单.md)。  
服务简介见：[当前服务简单介绍.md](./当前服务简单介绍.md)。  
HTTP 设计见：[source-http-api-设计说明.md](./source-http-api-设计说明.md)。

## 六、选型建议（简表）

| 你要… | 优先选用 |
|------|----------|
| 把立方体/专题图给算法或 GIS | GeoTIFF |
| 对接处理中心历史高光谱库 | ENVI（可再转 GeoTIFF） |
| 按田块统计、Web 传矢量 | GeoJSON |
| 对接传统地块库 | Shapefile（或转 GeoJSON） |
| 传轨迹/光谱表 | CSV |
| 给业务系统结论 | JSON 报表 + 专题图路径 |
